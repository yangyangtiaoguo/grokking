## 2. Structural Patterns

- **Empirical-phenomenology papers in this genre lead with the map, not the mechanism.** Double descent, Omnigrok, and Power et al. all open Results with the raw phenomenon (a plot/table showing the effect exists and where), and only afterward introduce candidate mechanistic explanations, clearly flagged as candidate/partial. This paper's already-planned Results ordering (4.1 Failure Map and Kinetics → 4.2 Coverage Intervention → 4.3 Boundary Candidate Summary as a sub-analysis → 4.4 Robustness/Transfer) follows this pattern correctly — the mechanism-discrimination material (C4) is appropriately placed after and subordinate to the map itself.
- **Ablations/controls are usually presented as a small number of maximally-informative, orthogonal comparisons**, not an exhaustive grid. Nanda et al.'s progress-measure paper and this paper's `same_dist`/`rare_short`/`uniform` triplet both follow "three conditions that each rule out one specific alternative explanation" rather than a large uninterpretable sweep.
- **Limitations are placed as their own labeled subsection near the end of Discussion**, itemized rather than narrative, in the more recent exemplars (post-2022) — matches this paper's existing plan.

## 3. Rhetorical Patterns

- **Appropriate hedging vs. defensive over-hedging.** The exemplars hedge exactly once, at the point of the actual limitation, and state the limitation as a factual boundary condition ("we do not observe X beyond scale Y") rather than a string of stacked disclaimers ("it is worth noting that this might possibly suggest, though we do not claim..."). This paper's audit-mandated wording ("among the tested interventions," "finite-budget empirical phase diagram," "qualifies rather than confirms") is already at the correct hedging density — each qualifier does real work, restricting a specific over-claim, rather than being reflexive throat-clearing. Care should be taken during drafting not to add MORE hedges around these already-precise phrases; adding redundant hedging on top of a precisely-scoped claim reads as anxious rather than careful.
- **"We predicted X, found not-X" narrative.** Omnigrok's own narrative arc (weight norm, not weight decay per se, is the real driver — a correction to the simpler "weight decay causes grokking" folk explanation) is a close structural analogue to this paper's own arc (the original proposal predicted the phase boundary would move one direction with skew; the data showed the opposite direction, and the corrected picture is more interesting). The rhetorical move in both cases: present the initially-wrong prediction briefly, present the corrected empirical finding as the actual contribution, and frame the correction as evidence the empirical approach was necessary (a purely theoretical derivation would have gotten the direction wrong) — this is a strength narrative, not an admission of failure, and should be written with that confidence in Discussion.
- **Null/negative results stated as plainly as positive ones**, same sentence structure and same section, not relegated to a footnote or buried in an appendix aside. E.g., "candidate p_star was pre-registered and rejected" should read with the same declarative confidence as "candidate E_c was the best-ranked fit," not as an apologetic aside.

## 4. Language Patterns

- **Phase diagrams**: describe axes and the classification rule before describing the pattern ("we classify each (α, weight-decay) cell as GROK/TRAP/CRUSH/PARTIAL using thresholds τ on A_unif and A_hi... the resulting map shows two failure regions") — operational definition first, pattern description second. This mirrors Nanda et al.'s pattern of defining the progress measure before describing what it reveals.
- **Dose-response curves**: report the bracketing interval explicitly rather than a single point estimate when the underlying grid is coarse ("the transition is bracketed between doses of 0.39% and 0.78%" rather than "the critical dose is 0.78%") — this paper's audit-mandated wording already does this correctly and should be preserved verbatim in the final prose.
- **Ablation tables**: state the prediction BEFORE the result in text discussing pre-specified/preregistered comparisons ("we predicted that reducing width would make grokking harder; it did (Table X)") rather than presenting the result first and retrofitting the prediction narrative — this ordering is what makes a pre-specification claim readable as genuinely pre-specified rather than post-hoc-sounding even when it is genuinely pre-specified.
- **Honest null/negative results**: use the same register as positive findings — declarative, specific, quantified — e.g. "the SGD+momentum condition showed near-chance performance (mean accuracy 0.001) but was not separately tuned, so this result should be read as an untuned optimizer-transfer failure, not a controlled comparison of optimizers" is the correct register: specific finding, specific caveat, no vague throat-clearing.
